# Kaggle cells — Task 5: paired protocol-match re-run, all 32 checkpoints home

**Session settings (both required):**
- Accelerator: **GPU T4 x2**
- Internet: **ON** (Zoobot downloads from HuggingFace on first use)

**What this session produces:** `nb0_image` and `nb3`, both at Zoobot v2.0.1 defaults
(`head_lr` = `backbone_lr` = 1e-4, `weight_decay` = 0.05, `lr_decay` 0.75, cosine off),
8000 steps, 32 curve points, **all 32 checkpoints per run**, packaged into verifiable
sub-500 MB parts.

**The validator study does NOT run here.** It runs locally after the download, on the
checkpoints this session brings home.

---

## Ordering decision: CONCURRENT

**Chosen: both rungs run at the same time**, GPU 0 = `nb0_image`, GPU 1 = `nb3`, with the
§1 reference **declared up front** by Cell 3.

The reason sequential was ever on the table is that `run_config.json` is normally written
only *after* training, so `nb3` would have to wait for `nb0` to finish before it had
anything to validate against. `--emit-config` (added for this task) builds the config from
the *same construction code* the real run uses and writes it without training, so the
reference exists at minute 2.

**This does not weaken the §1 check**, because of three things together:

1. The declared reference is machine-generated by the runner itself, not hand-written.
2. `nb3` validates against it exactly as before — all 15 pinned keys, no relaxation.
   (Verified locally: only `n_blocks`, and the exempt `grad_checkpointing`, differ.)
3. **`package_screen_results.py` re-checks the declared reference against the config `nb0`
   ACTUALLY emitted, on every pinned key, and refuses to package if they differ.** So a
   fabricated or stale reference cannot survive to the deliverable.

The control gate is also not a sequencing constraint: with `--control-scores` it reads the
**uploaded historical dumps**, never the new run. Verified locally — it passes
(diff −0.0714, CI [−0.1327, +0.0000] contains 0), and the hyperparameter change cannot
affect it because the gate compares two frozen score dumps produced by an unchanged code
path.

Cost of the choice: **~2.9 h instead of ~4.1 h**, and `nb3` (the long pole) starts
immediately rather than after a 68-minute wait.

## Wall-clock projection vs the session cap

These are **measured on Kaggle T4**, taken from `results.json` / logs of the Task-3 session
— not extrapolated from the local card. Better still, they were measured *while both GPUs
were busy*, so contention is already in the numbers.

| stage | basis | time |
|---|---|---|
| setup (pip, unzip, encoder download) | Task-3 session | ~10 min |
| GPU 0 — `nb0_image`, 8000 steps + 32 curve points | **measured 68.3 min** | 68 min |
| GPU 1 — `nb3`, 8000 steps + 32 live-encode curve points | **measured 176.5 min** | 177 min |
| concurrent wall clock = max(GPU0, GPU1) | | **177 min** |
| packaging: tar 1.9 GB + sha256 + streamed reassembly verify | estimate | ~10 min |
| **TOTAL** | | **≈ 3.3 h** |

Against Kaggle's **12 h session cap: ~27% used.** Very comfortable.

Two notes on why this is conservative:
- The measured 176.5 min for `nb3` was recorded while GPU 0 ran `nb0_image` **and then
  `nb1`** — i.e. under contention for the whole 3 hours. Here GPU 0 goes idle after 68 min,
  so `nb3` should finish at or before 177 min.
- Hyperparameters do not change step time, so the protocol match does not move these.

Sequential, for comparison: 68 + 177 + 20 = **≈ 4.4 h**. Also fits, but with no benefit.

> The estimate I gave at the end of Task 4 (~2.3 h sequential / ~1.7 h concurrent) was
> extrapolated from the **local RTX 4050** benchmark and was optimistic. The T4 is roughly
> 1.5× slower (same `nb0_image` run: 46.2 min local vs 68.3 min on T4). The table above
> supersedes it.

## Cell 3 — launch both GPUs concurrently, blocking with progress

```python
import os, subprocess, time, glob
from pathlib import Path
WORK = Path("/kaggle/working"); SCRIPTS = WORK/"scripts"
DATA = Path(os.environ["LENS_DATA_ROOT"])
SRC  = Path([p for p in Path("/kaggle/input").rglob("MANIFEST.json")][0]).parent
CTRL = SRC/"control_scores"; REF = WORK/"ref_zoobot"/"run_config.json"
LOGS = WORK/"logs"; LOGS.mkdir(exist_ok=True)
RUNS = WORK/"runs"

COMMON = (f'--data-root "{DATA}" --splits "{DATA}/splits/splits.json" '
          f'--cache-dir "{DATA}/feature_cache" --fp16 --num-workers 2 '
          f'--control-scores "{CTRL}" --reference-config "{REF}"')

# GPU 0 -- the new frozen reference at Zoobot defaults. --dir-suffix _zoobot keeps it
# distinct from the pre-protocol-match runs already in runs/.
gpu0 = (f'cd {SCRIPTS} && CUDA_VISIBLE_DEVICES=0 python run_screen_unfreeze.py '
        f'--run nb0_image --dir-suffix _zoobot {COMMON} '
        f'> {LOGS}/nb0_image_zoobot.log 2>&1')

# GPU 1 -- nb3. --grad-checkpointing is REQUIRED: numerically exact (test 8), and without
# it a true-batch-256 backward through stages[1..3] does not fit.
gpu1 = (f'cd {SCRIPTS} && CUDA_VISIBLE_DEVICES=1 python run_screen_unfreeze.py '
        f'--run nb3 --grad-checkpointing {COMMON} > {LOGS}/nb3_zoobot.log 2>&1')

t0 = time.time()
p0 = subprocess.Popen(["bash","-lc",gpu0]); p1 = subprocess.Popen(["bash","-lc",gpu1])
print(f"GPU0 pid {p0.pid}  nb0_image_zoobot   (expect ~68 min)")
print(f"GPU1 pid {p1.pid}  nb3 + checkpointing (expect ~177 min)")
print("This cell BLOCKS until both finish. Progress every 5 min.\n", flush=True)

BAD = ("Traceback","ABORT","REFUSING","OOM","MISMATCH","FAILED CLOSED","retention failed")
while True:
    d0, d1 = p0.poll(), p1.poll()
    el = (time.time()-t0)/60
    line = [f"[{el:6.1f} min]"]
    for tag, d, log in (("nb0",d0,"nb0_image_zoobot.log"), ("nb3",d1,"nb3_zoobot.log")):
        pat = str(RUNS/("baselineA_fold0_nb0_image_zoobot" if tag=="nb0"
                        else "baselineA_fold0_nb3"))
        n = len(glob.glob(os.path.join(pat,"checkpoints","step_*.pt")))
        state = "running" if d is None else (f"DONE rc={d}")
        line.append(f"{tag}: {n:>2}/32 {state}")
    print("  ".join(line), flush=True)
    for log in ("nb0_image_zoobot.log","nb3_zoobot.log"):
        p = LOGS/log
        if p.is_file():
            for l in p.read_text(errors="replace").splitlines():
                if any(k in l for k in BAD):
                    print(f"   !! {log}: {l.strip()[:160]}", flush=True)
    if d0 is not None and d1 is not None:
        break
    time.sleep(300)

print(f"\nBOTH FINISHED in {(time.time()-t0)/60:.1f} min  (nb0 rc={p0.poll()}, nb3 rc={p1.poll()})")
assert p0.poll() == 0, "nb0_image FAILED -- see logs/nb0_image_zoobot.log"
assert p1.poll() == 0, "nb3 FAILED -- see logs/nb3_zoobot.log"
for d in sorted(glob.glob(str(RUNS/"baselineA_fold0_*"))):
    n = len(glob.glob(os.path.join(d,"checkpoints","step_*.pt")))
    print(f"  {os.path.basename(d):<44} {n}/32 checkpoints")
```

Expected shape at real sizes (`nb3` checkpoint = 59.4 MB):

| part | contents | size |
|---|---|---|
| `screen_core.tar.gz` | curves, configs, results, score dumps, logs, **all 32 nb0 checkpoints** (17 KB each) | ~1 MB |
| `ckpt_baselineA_fold0_nb3_part01of04.tar` | steps 250–2000 | 475.2 MB |
| `ckpt_..._part02of04.tar` | steps 2250–4000 | 475.2 MB |
| `ckpt_..._part03of04.tar` | steps 4250–6000 | 475.2 MB |
| `ckpt_..._part04of04.tar` | steps 6250–8000 | 475.2 MB |

Each `ckpt_*` part is a **self-contained tar** — extract in any order, and re-download one
failed part without re-fetching the rest. `MANIFEST.json` carries per-part size, sha256,
file count and the exact steps inside.

Checkpoints are stored **uncompressed**: they are float32 weights, deflate barely shrinks
them, and compressing 1.9 GB would cost session minutes for a few percent.

### One code change is still needed before nb3's checkpoints can be used

**Bringing the checkpoints home is necessary but not yet sufficient.** `study_validators.py`
scores every checkpoint from `data/feature_cache`, which is only valid for a **frozen**
encoder. An `nb3` checkpoint carries an encoder delta (`encoder_trainable`, 120 tensors), so
the cached 640-d features are stale for it. Measured on a real `nb3` checkpoint:
cache-scored TPR **0.194** vs logged **0.020** — not a rounding difference, a different
model.

This currently fails *safe*: the study detects `n_blocks > 0`, skips the run with an
explicit message, and leaves IM/SND/ATC as `n/a` rather than reporting numbers computed from
stale features. But it does mean a follow-up is required:

> Score unfrozen checkpoints through `live_encode.py` with the encoder reconstructed as
> **base Zoobot weights + the checkpoint's `encoder_trainable` delta**, then verify the
> recomputed real-test TPR against `curve.csv` before trusting any validator — exactly the
> reconstruction gate the frozen path already passes bit-exactly.

The checkpoints this session produces contain everything that needs (head, standardizer,
and the full encoder delta), so the change can be written and tested against real artifacts
once they are downloaded — which is better than guessing at it now. Cost: forward-only
re-encoding of ~39 k images × 32 checkpoints, i.e. real GPU time, unlike the frozen path
which was free.

## Scaling flag — this approach does NOT extend to the full bake-off

**Flagged, not solved,** per the brief.

At `nb3` size, 32 checkpoints is 1.9 GB for **one fold of one method**. The full matrix —
4 methods × 5 folds × 32 checkpoints × 59.4 MB — is **≈ 38 GB**. That breaks in three
places at once:

- **Kaggle working dir**: ~20 GB, so 38 GB does not even land, let alone land alongside its
  own archives (which would need another 38 GB).
- **Download**: ~80 sub-500 MB parts through a browser is not a workflow.
- **Local disk**: 38 GB of checkpoints to store and re-read for every study.

It is also mostly waste: the checkpoints exist *only* to recompute per-checkpoint validator
scores, and those scores are a few KB per checkpoint. Directions worth evaluating when this
becomes live (none investigated yet, all UNVERIFIED here):

1. **Dump the derived quantities, not the weights.** Write the target-pool logits, source-val
   logits and test scores at each curve point (~40 k floats ≈ 160 KB/checkpoint → ~200 MB for
   the whole matrix, a 190× reduction). This is sufficient for IM / SND / ATC / agreement and
   everything else in `validators.py`, which consume scores rather than weights. The cost is
   that a validator invented *later* and needing a different intermediate cannot be
   backfilled without re-running.
2. **Keep weights only where the curve has spread.** A flat curve has nothing to select
   between, so full checkpoints matter most on the runs that move.
3. **Store head-only deltas for unfrozen runs.** Most of `nb3`'s 59.4 MB is the encoder
   delta; the head is 17 KB. Whether the encoder delta is needed depends on whether the
   validator recomputes features — SND-on-features does, SND-on-predictions does not.

Option 1 is the obvious first candidate and would have made this entire session unnecessary,
but it needs a decision about which intermediates to freeze, and that decision should be
made deliberately rather than as a side effect of Task 5.
